# 에이전트화 계획안

`Stock_Agent_에이전트화_계획안.pptx` — 31장. 대형 증권사 조직을 그대로 옮기되,
논문은 상시 갱신되고 에이전트는 이벤트로 소집되는 구조.

> **계획안입니다. 아직 구현하지 않았습니다.**

## 구성

| 부 | 내용 |
|---|---|
| PART 1 · 지금 | 현재 자산 진단 · 왜 에이전트화인가 · 깨면 안 되는 다섯 가지 |
| PART 2 · 논문을 살린다 | 12편은 스냅샷 · 파이프라인 5단계 · **재현 관문** · 감가/은퇴 · 논문 원장 |
| PART 3 · 조직과 에이전트 | 목표 조직도 · 데스크 카탈로그 · 상설 vs 소집 · 생명주기 · 트리거 · 부하 · 에스컬레이션 |
| PART 4 · 통제 | 정보교류차단 · 권한 매트릭스 · 봉투 스키마 · 일곱 게이트 · 스코어카드 |
| PART 5 · 실행 | 기술 스택 · MCP 설계 · 하루 운영 · 로드맵 · 리스크 · 착수와 KPI |

## 세 가지 핵심

**1. 재현 관문 (PART 2)**

채택본 12편은 전부 미국 표본 논문인데, 코스닥에서 성립하는지 확인한 적이 없다.
인용은 검증이 아니다.

논문에서 방향 있는 한 문장을 뽑아 → `ki.sqlite` 일봉으로 그 팩터를 계산 →
코스닥 전종목 분위 스프레드의 부호를 논문과 대조 → **재현된 것만 채택**한다.
판정은 `재현됨 / 방향 반대 / 판정 불가` 셋 중 하나이고, 실패도 지우지 않는다.

`.papers.json` 은 목록에서 append-only 원장(`ki.papers/2`)이 된다.
반감기 180영업일마다 재검, 1회 실패는 `warned`, 연속 2회면 `retired`.

**2. 이벤트 소집 (PART 3)**

상설은 셋(data-ops · compliance · ic-chair)뿐이고 나머지는 트리거로 소집된다.
공시 1건 = 인스턴스 1개. `spawn → 작업 → 봉투 → 소멸`. 무상태라 같은 입력이면
같은 봉투가 나오고, 그래서 리플레이가 된다. 전수 340회/일 → 그날 변동분만.

**3. 벽 (PART 4)**

증권사가 고유계정과 리서치를 나누듯 원장과 에이전트를 나눈다.
**인스턴스가 1개든 400개든 쓰기 도구를 받는 인스턴스는 없다.** MCP 서버에
쓰기 도구를 만들지 않는 것이 벽이다 — 규칙이 아니라 구조.

## 깨지 않는 것

CLAUDE.md 의 다섯 규칙 그대로다.

| 기존 규칙 | 에이전트 적용 |
|---|---|
| 재기만 하고 판단하지 않는다 | 게이트 ① 판정 어휘 |
| 원장에는 측정한 사실만 쓴다 | MCP 에 쓰기 도구 미노출 |
| 없는 값을 만들지 않는다 | 봉투 null 허용 · 게이트 ⑤ 신선도 |
| 재료에는 등급이 있다 | 다섯 번째 등급 **'해석'** 신설 · 게이트 ② |
| 키·대외비는 저장소 밖 | 출력 `scrub()` 강제 · 게이트 ⑥ |

에이전트 산출은 무엇을 근거로 삼았든 등급 '해석'이며 1차로 승격되지 않는다.
게이트는 6개 → **7개**(재현 관문 추가).

## 먼저 알아야 할 숫자

이 숫자가 이 방안 전체의 출발점이다 (로드맵 P2, W3–4).

## 자료 재생성

```bash
python docs/agentization/sprites/sprites.py     # 픽셀 스프라이트 → PNG
npm install pptxgenjs
node docs/agentization/build_deck.js "Stock_Agent_에이전트화_계획안.pptx"
```

스프라이트는 문자 그리드를 PIL 로 구워 nearest-neighbour 확대한 것이다.
외부 이미지·CDN 을 쓰지 않는다. 차트 계열색은 명도 밴드·CVD 분리·대비 검사를
통과시킨 값이다.
