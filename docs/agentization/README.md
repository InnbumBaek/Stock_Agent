# 에이전트화 방안 — 대형 증권사 조직 모델

`Stock_Agent_에이전트화_방안.pptx` (19장) 의 근거와 재생성 방법입니다.

## 무엇을 제안하는가

지금의 파이프라인은 **측정**까지 완성돼 있습니다 (`ki_monitor.py` 8,684줄 ·
자체 검증 128개 · 공식 API 5종). 부족한 것은 그 산출물을 읽어 회의 쟁점으로
바꾸는 **사람의 시간**입니다. 그래서 대형 증권사 조직을 그대로 옮겨 여덟 개
데스크로 나눠 읽게 합니다.

핵심은 **정보교류차단**입니다.

```
측정층                      벽                     판단층
ki.sqlite 원장   →   MCP ki-ledger (읽기 전용)   →   데스크 8개
data-ops 단독 쓰기      쓰기 도구 자체가 없음        산출 등급 = '해석'
```

벽은 프롬프트가 아니라 **도구 노출**로 세웁니다. MCP 서버에 쓰기 도구를 만들지
않으므로 에이전트는 원장을 고칠 방법 자체가 없습니다.

| 데이터·IT | `data-ops` | 원장 쓰기 단독 |
| 의결 | `ic-chair` | 조립만 한다. 판단하지 않는다 |

## 지키는 것 — CLAUDE.md 다섯 규칙의 에이전트 대응

| 기존 규칙 | 에이전트 적용 |
|---|---|
| 재기만 하고 판단하지 않는다 | 게이트 ① 판정 어휘 |
| 원장에는 측정한 사실만 쓴다 | MCP 쓰기 도구 미노출 (구조적 차단) |
| 없는 값을 만들지 않는다 | 봉투 스키마 null 허용 + 게이트 ④ 신선도 |
| 재료에는 등급이 있다 | 다섯 번째 등급 **'해석'** 신설 + 게이트 ② |
| 키·대외비는 저장소 밖 | 출력 `scrub()` 강제 + 게이트 ⑤ |

에이전트 산출물은 무엇을 근거로 삼았든 등급이 **'해석'** 이며, 1차로 승격되는
경로가 없습니다.

## P0 — 방안 승인과 무관하게 즉시 처리

압축 파일의 `stock-monitor/env.txt` 에 KRX · DART · ECOS · FRED · KIS(앱키 +
시크릿) **6종 키가 평문**으로 들어 있었습니다. 파일명이 `.env` 가 아니라
`env.txt` 여서 기존 `.gitignore` 의 어떤 규칙에도 걸리지 않습니다.

- 이 커밋은 `env.txt` 를 **저장소에 넣지 않았습니다.**
- `.gitignore` 두 곳에 `env.txt` · `env*.txt` · `*.env.txt` 규칙을 추가했습니다.
- **키 6종은 폐기·재발급이 필요합니다.** 노출된 키는 재발급 외에 되돌릴 방법이
  없습니다.
