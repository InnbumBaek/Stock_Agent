논문은 상시 갱신되고 에이전트는 이벤트로 소집되는 구조.

## 먼저 볼 것 — 3장 「한 장으로」

## 세 가지 핵심

**1. 재현 관문 (PART 2)**

채택본 12편은 전부 미국 표본 논문인데, 코스닥에서 성립하는지 확인한 적이 없다.
인용은 검증이 아니다.

논문에서 방향 있는 한 문장을 뽑아 → `ki.sqlite` 일봉으로 그 팩터를 계산 →
코스닥 전종목 분위 스프레드의 부호를 논문과 대조 → **재현된 것만 채택**한다.
판정은 `재현됨 / 방향 반대 / 판정 불가` 셋 중 하나이고, 실패도 지우지 않는다.

**주 1회 도는 사이클이지, 일회성 배치가 아니다.** 월요일 07:30 에 수확 →
심사 → 재현 → 채택이 한 바퀴 돌고, 같은 사이클에 반감기가 도래한 기존
채택본도 함께 태워 재검한다(주 최대 3편).

`.papers.json` 은 목록에서 append-only 원장(`ki.papers/2`)이 되고, state 는
네 가지다.

| state | 뜻 | 인용 |
|---|---|---|
| `unverified` | 이관됐지만 아직 재검 순번이 안 옴 | 가능 — '미검증' 표시가 붙는다 |
| `adopted` | 재현 통과 | 가능 |
| `warned` | 재검 1회 실패 | 가능 — 경고가 함께 나간다 |
| `retired` | 연속 2회 실패 | **차단** |

기존 12편은 `unverified` 로 이관된다. 반감기는 **원 채택일 기준**이라 12편이
전부 도래 상태로 들어오지만, **주 3편 상한이 자연히 분산**시켜 4주에 걸쳐
소화된다. **12편을 한꺼번에 검사하는 단계는 없다.**

**2. 데스크는 네 질문이 정한다 (PART 3)**

이 도구의 목적은 **회수 판단 회의 자료**이고, 답해야 하는 것은 네 질문이다.
`.papers.json` 의 논문조차 이미 질문으로 태그돼 있다 (q1:3 · q2:5 · q3:2 · q4:2).

| 질문 | 데스크 | 담당 절 |
|---|---|---|
| q1 얼마나 왔는가 | `q1-progress` 진척역 | §1 · §5 · §7 · §9 |
| q2 팔 수 있는가 | `q2-disposal` 처분역 | §2 · §6 · §8 · §11 · §13 · §14 · §15 |
| q3 어떻게 팔 것인가 | `q3-execution` 집행역 | §3 |
| q4 지금이 그 때인가 | `q4-timing` 시점역 | §4 · §12 · §18 |

여기에 방법론 1 (`quant-method`), 통제 3 (`risk-officer` · `compliance-officer` ·
`data-ops`), 조립 1 (`ic-chair`) 을 더해 **아홉**이다.
상설은 셋이고 나머지 여섯은 그 질문의 답이 달라졌을 때만 소집된다.

> 앞선 안은 CATALOG(무슨 데이터가 있나)에서 데스크를 20개로 뽑았다. 그건
> 데이터 목록이지 결정 목록이 아니다. §16 스코어카드처럼 네 질문 중 어느
> 것도 바꾸지 않는 절에도 담당이 생기는 것이 그 증거다.

**3. 이벤트 소집 (PART 3)**

상설은 셋(data-ops · compliance · ic-chair)뿐이고 나머지는 트리거로 소집된다.
공시 1건 = 인스턴스 1개. `spawn → 작업 → 봉투 → 소멸`. 무상태라 같은 입력이면
같은 봉투가 나오고, 그래서 리플레이가 된다. 역할이 20개로 늘면 전수는 더 나빠진다 — 85종목 × 종목단위 7데스크 = 595회/일.
역할을 늘릴수록 소집이 더 중요해진다. 상설 5 + 소집 15.

**4. 벽 (PART 4)**

증권사가 고유계정과 리서치를 나누듯 원장과 에이전트를 나눈다.
**인스턴스가 1개든 400개든 쓰기 도구를 받는 인스턴스는 없다.** MCP 서버에
쓰기 도구를 만들지 않는 것이 벽이다 — 규칙이 아니라 구조.

## 깨지 않는 것

CLAUDE.md 의 다섯 규칙 그대로다.

| 기존 규칙 | 에이전트 적용 |
|---|---|
| 재기만 하고 판단하지 않는다 | 게이트 ① 판정 어휘 |
| 원장에는 측정한 사실만 쓴다 | MCP 에 쓰기 도구 미노출 |
| 없는 값을 만들지 않는다 | 봉투 null 허용 · 게이트 ⑤ 신선도 |
| 재료에는 등급이 있다 | 다섯 번째 등급 **'해석'** 신설 · 게이트 ② |
| 키·대외비는 저장소 밖 | 출력 `scrub()` 강제 · 게이트 ⑥ |

에이전트 산출은 무엇을 근거로 삼았든 등급 '해석'이며 1차로 승격되지 않는다.
게이트는 6개 → **7개**(재현 관문 추가).

## 구현 규격 (33장)

구현할 때 임의로 정하게 될 값들을 미리 못박아 두었다 — 재현 관문 판정 기준
(유니버스 · 최소 표본 · 5분위 · Newey-West t · |t| ≥ 2.0), 트리거 임계값,
봉투 필수 필드, 예산 상한, 게이트 ① 차단 어휘 목록.

제안값이며 착수 전에 확정해야 한다. **이 값들이 Phase 1 의 실제 산출물이다.**
