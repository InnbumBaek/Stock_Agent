# agents/ — 판단층

측정층(`stock-monitor/ki_monitor.py`)은 **재기만 한다.** 이 층은 그것을 읽어
문장으로 만든다. 그리고 둘 사이에 관문을 둔다.

문장은 숫자와 달리 조용히 틀린다. "처분에 12영업일" 이라는 말은 그 자체로는
근거의 등급도, 언제 잰 값인지도, 그 방법이 무엇을 주장하지 않는지도 담지
않는다. 회의에서 위험한 것은 틀린 숫자가 아니라 **등급이 지워진 숫자**다.

`ki_monitor.py` 는 열지 않는다. CRLF 파일이라 편집 도구가 줄바꿈을 바꾸면 파일
전체가 diff 에 잡히고 실제 변경이 그 안에 묻힌다. 감싸기만 한다.

```
envelope.py       모든 주장이 입는 형식 (측정값 + 등급 + 가정 + 한계)   16
papers.py         논문 장부 ki.papers/2 — 네 상태 · append-only        19
replication.py    분위 러너 — 달력 시간. 결정적이다                     25
eventstudy.py     이벤트 러너 — 사건 시간. 두 통계를 나눠 쓴다          16
gates.py          게이트 ①~⑦. 통과 아니면 반려다                      20
triggers.py       트리거 스캐너 — 원장의 변화가 데스크를 부른다         16
ki_ledger_mcp.py  원장을 읽는 MCP 서버 · 읽기 10종. 쓰기 도구가 없다    27
cycle.py          주간 논문 사이클 — 감가 · 재검 · 기록                13
run_day.py        하루 운영 — 소집(작업지시서) · 게이트 → 발행         14
scorecard.py      계측. 고치지는 않는다                               11
replay.py         되짚기 — 봉투가 읽은 것과 지금 원장을 대조          12
                                                            합계  193
```

정의 파일은 저장소 루트의 `.claude/` 에 있다.

```
.claude/agents/   데스크 9개 — 질문 넷 · 계량 · 검산 · 준법 · 원장운영 · 간사
.claude/skills/   규칙 5종 — 등급 판정 · 봉투 작성 · 재현 · 채택 · 게이트
```

## 검증

```bash
python agents/selftest.py          # 193개. 키·네트워크·원장 없이 돈다
python agents/gates.py --selftest  # 모듈 하나만 돌릴 수도 있다
python docs/audit.py               # 정의 파일이 코드와 어긋나지 않는지
```

마크다운 정의 파일은 테스트가 돌려 보지 않는다. 데스크 이름 하나를 코드에서
바꾸고 `.md` 를 안 고치면 **트리거는 있는데 아무도 오지 않는 소집**이 생기고,
그것은 오류 한 줄 없이 "조용한 날"처럼 보인다. `docs/audit.py` 가 이름·개수·
임계가 코드와 맞는지 대조한다.

측정층의 128개와 나란히 돌린다. 검증이 두 곳으로 갈라지면 한쪽은 곧 안 돌게
된다.

## 네 가지 결정

### 1. 재현 임계는 t ≥ 3.0 이다

2.0 이 아니다. 2.0 은 검정을 **한 번** 할 때의 값이고, 주 1회 사이클이면 연
150회쯤 된다. 그때 2.0 은 아무 효과 없는 팩터를 해마다 7~8개 통과시킨다. 그
팩터들은 "논문 근거 있음" 딱지를 달고 회의에 올라간다 — 이 시스템이 막으려고
만들어진 바로 그 실패다.

근거는 Harvey·Liu·Zhu (2016) RFS 29(1) 5-68 이고, 그 논문은 `.papers.json` 의
`method_papers` 에 **한계와 함께** 들어 있다. 3.0 은 보정 방식과 가정한 검정
횟수에 따라 달라지는 값이지 자연상수가 아니다.

대가가 있다. 통과가 드물어진다. 그것이 의도다 — 이 관문은 통과시키려고 만든
것이 아니라 가려내려고 만든 것이다.

### 2. 기존 12편은 `unverified` 로 들어갔다

`adopted` 가 아니다. 사람이 읽고 고른 좋은 논문들이지만, 우리 원장에 대고
계산해 본 적은 없다. 재현 관문을 만들면서 기존 항목만 통과한 것으로 쳐 주면
그 관문은 **처음부터 빈 관문**이다.

`unverified` 는 인용을 막지 않는다. '미검증' 표시를 달고 나간다. 주 1회
사이클로 돌리면 어느 시점에나 아직 재현을 돌리지 못한 논문이 남고, 그것을 전부
막으면 관문이 아니라 정지 버튼이 된다.

인용이 실제로 막히는 것은 `retired` 뿐이다.

### 3. MCP 서버의 권한은 프롬프트가 아니라 도구 목록이 정한다

에이전트에게 "원장에 쓰지 마라"고 부탁하지 않는다. 쓰는 도구를 주지 않는다.
프롬프트로 건 금지는 프롬프트가 길어지면 희미해지고 모형이 바뀌면 같이 바뀐다.

세 겹이다 — ① 쓰기 도구가 없다 ② 연결이 `mode=ro` 다 ③ 생 SQL 을 받지 않는다.

열 개 전부 읽기다. 여덟은 원장(`ki.sqlite`)을, `papers` 는 논문 장부를,
`calendar` 는 일정표를 읽는다. 뒤의 둘은 원장이 없어도 답한다 — 다른 파일이기
때문이다.

**데스크가 `papers` 를 읽을 수 있어야 한다.** 읽지 못하면 봉투의
`method.paper_state` 를 추측해서 적게 되고, 게이트 ③ 이 장부와 어긋난다고
반려한다. 데스크가 볼 수 없는 것을 근거로 반려하는 관문은 관문이 아니라
함정이다.

### 4. '해석' 은 어떤 등급으로도 승격되지 않는다

CLAUDE.md 규칙 4 의 네 등급에 다섯 번째를 더했다. 앞의 넷은 재료의 등급이고,
'해석' 은 **데스크가 만든 문장**의 등급이다.

에이전트가 1차 자료를 읽고 쓴 문장은 1차 자료가 아니다. 읽은 재료가 KRX
였다는 사실이 그 해석을 KRX 로 만들지 않는다. 승격 경로를 아예 없애 두지
않으면, 몇 단계를 거치는 사이에 누군가의 추측이 공식 통계의 얼굴로 회의에
올라온다.

## MCP 서버 쓰기

`.claude/settings.json` 에 `ki-ledger` 로 등록돼 있다. 원장이 없어도 서버는
서고, 도구를 부르면 "`ingest` 를 먼저 하십시오" 라고 답한다 — 세션마다 죽어
있는 서버보다 사유를 말하는 서버가 쓸모 있다.

```bash
python agents/ki_ledger_mcp.py --db /경로/ki.sqlite   # 직접 세워 볼 때
```

### 5. 논문에는 세 가지 '아직'이 있다 — 섞으면 안 된다

장부의 논문이 전부 '아직 재현 안 됨'으로 남아 있으면 사이클이 밀리는 것처럼
보인다. 실제로는 셋이 섞여 있고 뜻이 다르다.

| 분류 | 어느 러너로 | 12편 중 |
|---|---|---|
| `testable` | `replication.py` — 달력 시간 분위 정렬 | **6** — amihud2002 · dnr1998 · jt1993 · j1990 · gh2004 · ahxz2006 |
| `event_time` | `eventstudy.py` — 사건 시간 | **2** — ritter1991 · fh2001 |
| `not_a_factor` | 없음. 분위 정렬로 검정할 물건이 아니다 | **4** — roll1984 · cs2012 · ac2000 · athl2005 |
| `needs_runner` | 아직 없다 | **0** — 지금은 비어 있다 |

**검정 대상 8편.** 나머지 넷은 못 한 것이 아니라 **원래 이 관문의 대상이
아니다.** 추정량과 모형은 "이런 종목이 더 오른다"를 주장하지 않으므로 분위로
정렬해 초과수익을 볼 물건이 아니고, 검증은 다른 추정량이나 실측 체결가와
대조하는 방식이어야 한다.

`roll1984` 와 `cs2012` 는 **스프레드 추정량**이다. 수익률 방향을 주장하지
않으므로 분위로 정렬해 초과수익을 볼 물건이 아니고, 검증은 다른 추정량이나
실측 체결가와 대조하는 방식이어야 한다. `ac2000` · `athl2005` 도 마찬가지로
집행 **모형**이다.

`ritter1991` · `fh2001` 은 **이벤트 시간**으로 재야 한다. 각 종목의 기준일이
다르기 때문에 달력으로 줄을 세우면 사건이 서로 상쇄돼 아무것도 안 보인다.
`eventstudy.py` 가 이 둘을 돌린다.

`ahxz2006` 의 고유변동성은 **일간** 잔차 변동성이다. 월말 종가로 대용하면 다른
측정에 논문 이름을 붙이는 셈이라, 대신 일간 수익률을 지수에 회귀해 잔차의
표준편차를 잰다. 논문은 Fama-French 3요인 잔차를 쓰고 우리는 시장 하나만
쓰므로 **같은 양이 아니다** — 규모·가치 노출이 잔차에 남는다는 사실이
`limits` 에 적혀 나간다. 빈도는 논문과 같고, 남는 차이는 요인 수 하나다.

**`not_a_factor` 와 `needs_runner` 를 섞으면** "원래 이 관문의 대상이 아닌
것"과 "우리가 아직 못 한 것"이 구분되지 않는다. `selftest` 가 장부의 모든
논문이 넷 중 하나로 분류돼 있는지, 그리고 `event_time` 으로 분류한 논문에
**실제로 돌릴 러너가 있는지**를 검사한다. 분류만 바꿔 놓고 러너가 없으면
'대상 아님'을 '곧 할 것'으로 이름만 바꾼 셈이다.

`needs_runner` 는 지금 비어 있지만 목록과 검사는 남겨 뒀다. 비었다고 지우면,
다음에 그 칸을 쓰게 됐을 때 경로가 살아 있는지 아무도 모른다 — 가짜 항목을
잠깐 넣어 경로만 확인하는 검사가 들어 있다.

### 5-b. 이벤트 러너는 통계를 둘로 나눠 쓴다

섞으면 t 가 거짓말을 한다.

**긴 구간(상장 후 3년) — 달력시간 포트폴리오.** 종목마다 구간이 겹친다.
겹친 표본을 횡단면 t 로 재면 관측 수가 부풀려져 없는 효과가 유의하게 나온다.
매달 '해당 구간에 있는 종목' 포트폴리오를 만들어 그 시계열에 Newey-West 를
걸면 겹침이 포트폴리오 안으로 들어간다.

**짧은 창(해제일 ±5영업일) — 횡단면 CAR.** 겹침이 적어 횡단면 t 로 충분하다.
다만 같은 날 여러 종목이 풀리면 그 날짜에 몰린다 — 한계에 적혀 나간다.

### 6. 재생 가능성은 원장이 아니라 봉투가 만든다

회의에서 가장 어려운 질문은 "그때 왜 그렇게 읽었나"다. 석 달 전 봉투를 열어
지금 원장에 물어보면 다른 숫자가 나온다. 그때 둘 중 무엇인지 말할 수 없으면
그 시스템은 자기 이력을 설명하지 못한다.

    에이전트가 틀렸다     같은 자료를 보고 다르게 읽었다
    데이터가 바뀌었다     자료 자체가 그 뒤에 달라졌다

원장은 `INSERT OR REPLACE` 로 덮어써진다 (`ki_monitor.py` 의 유일한 쓰기
경로). 정정공시가 오면 같은 칸이 조용히 바뀌고 옛 값은 남지 않는다.

양방향 시간 장부로 바꾸려면 측정층을 건드려야 한다. **그래서 봉투 쪽에서
풀었다** — 값을 낸 봉투는 `read` 에 무엇을 읽었는지 적고, `replay.py` 가 그것을
지금 원장과 대조한다. 측정층은 한 줄도 건드리지 않았다.

```bash
python agents/replay.py --envelope 봉투.json
```

되짚기는 **판정하지 않는다.** 무엇이 움직였는지까지가 이 도구의 몫이고, 그
문장이 틀렸는지는 사람이 본다.

### 7. 조용한 날은 조용한 것이 정상이다

전수 실행은 종목 수에 고정으로 묶인다. 종목이 40개면 조용한 날에도 40번을
돌리고, 그 40번은 대부분 "달라진 것이 없다"는 말을 만들어 낸다. **할 말이
없는데 데스크를 돌려 말을 만들게 하는 것**이 이 구조가 막으려는 실패다.

트리거는 원장의 변화에서 나온다. 사람이 부르는 것이 아니라 데이터가 부른다.
상설 셋(`data-ops` · `compliance-officer` · `ic-chair`)만 매일 돌고, 질문
데스크는 그 질문의 답이 달라졌을 때만 소집된다.

재검은 **주 3편 상한**이다. 상한이 없으면 기한이 몰린 날 열두 편이 한 번에
소집되고, 그 주의 재현은 전부 대충 돌아간다.

## 하루

`SCHEDULE.cmd` 의 07:30 · 08:50 · 16:10 을 **바꾸지 않았다.** 사이에 끼워
넣었고, 월요일 07:40 에 주간 재현을 하나 더 걸었다.

```
07:30  수확 · 채택            기존 그대로
07:40  주간 재현 (월요일만)    agents/cycle.py --run   ← 새로 등록
08:50  리포트 + 소집          run_day.py --stage convene
장중    읽기만                 데스크는 돌지 않는다
16:10  종가 적재              data-ops 단독. 그날의 유일한 원장 쓰기
17:00  게이트 → 조립          run_day.py --stage publish
```

**장중에 데스크를 돌리지 않는 이유** — 일봉 장부 위에 세운 해석을 장중 값과
섞으면 무엇을 근거로 읽었는지가 시각마다 달라진다. 하루 한 번, 같은 기준일
위에서만 읽는다.

배치에 건 것은 `cycle.py` 뿐이다. 그것만이 **결정적 파이썬**이고 네트워크도
키도 쓰지 않는다. 데스크 작업은 LLM 이라 작업 스케줄러가 돌릴 수 없다 —
`run_day.py` 는 지시서를 내고 봉투를 받을 뿐, 그 사이를 대신 생각해 주지
않는다. 오케스트레이터가 판단에 손을 대면 데스크의 격리가 형식만 남는다.

## 아직 안 한 것 — 여기서 할 수 없는 것 둘

- **재현 러너를 진짜 원장에 물려 돌리는 것.** 합성 자료로는 러너가 맞다는
  것까지만 확인했다. 12편이 코스닥에서 실제로 어떻게 나오는지는 아직 모른다.
  `ki.sqlite` 는 87MB 이고 `.gitignore` 에 있어 이 환경에 없다.

  ```bash
  python agents/replication.py --paper amihud2002 --market KOSDAQ
  ```

- **`method_papers` 두 편의 Crossref 재대조.** 서지는 세 곳(OUP·NBER·RePEc)에서
  일치를 확인했지만, 이 환경의 이그레스 정책이 `api.crossref.org` 를 막아
  프로젝트 규율대로의 재대조를 하지 못했다. 네트워크가 열린 곳에서
  `docs/fetch_papers.py` 로 다시 볼 것.

둘 다 **환경 때문이지 미완이어서가 아니다.** 코드는 두 경우 모두 준비돼 있다.
